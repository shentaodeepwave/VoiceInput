## 2. 项目背景与目标

### 痛点
手动打字效率低，尤其在多任务场景下，频繁切换打断思维。语音输入可以解放双手，提升文本输入速度。
考虑到当下的程序员行业，与Agent交互开发逐渐成为主流，作者认为可以开发一款一键傻瓜式语音转文字输入法助手，彻底抛弃传统的手动键入-输出式交互逻辑。

### 真正的痛点
> 手动和 agent 打字对话太累了，我们想躺着只动嘴就能奴役 AI。

### 核心目标
制作一个**轮椅级友好的语音输入法** —— 保证你甚至连鼠标都没有的情况下，文本输入速度不输金山打字王。

### 比赛要求对齐
- 准确度：安静环境下 ≥95%
- 易用性：打开程序 → 点击录音 → 说话 → 出文字，不超过 2 步
- 响应速度：实时显示
- 成本：单次识别 <≈0.002 元

## 3. 用户与核心场景

| 用户 | 场景 | 需求 |
|------|------|------|
| 学生小王 | 一边开发项目一边打王O荣耀，腾不出手 | 仅需动动嘴就能告诉agent要干什么活，不耽误操作 |
| 社畜小高 | 一边求职一边打火O忍者 | 在不中断 PVP 的情况下，用语音回复骚扰信息 |

## 4. 功能范围（DoD）

### 4.1 P0 核心功能

| 功能点 | 用户故事 | 验收标准 |
|--------|----------|----------|
| 麦克风权限 | 作为用户，我希望程序启动时自动申请权限 | 启动后弹窗请求；若拒绝，提供设置入口重新授权 |
| 语音录制 | 我希望长按（或点按）按钮开始/结束录音 | 长按录音，松开即停止；或点按开始，点按结束 |
| 文字转写 | 我希望说的话能准确变成文字 | 调用云端 API，错误率 <10%（安静环境） |
| 文本编辑 | 我可以修改识别错误，一键复制或清空 | 文本框可手写编辑；提供“复制”“清空”按钮 |

### 4.2 P1 增强功能

| 功能点 | 说明 |
|--------|------|
| 响应时间显示 | 显示本次识别耗时（ms） |
| VAD 静音自动停止 | 检测到静音 ≥2.0s 自动结束录音 

注意到在不同工作环境下，用户对于VAD的响应延迟存在不同需求，如日常聊天或是快速交流时，需要高效率响应速度（即VAD静音检测时长更短），反之，在工作交流或是项目对接时，则更偏向斟酌语句与考虑语言的精确性，这时就需要低效率响应速度（VAD响应延迟更长），因此，我们设计了可以根据用户需求的不同，所进行调整的几种模式，也支持用户diy自己喜好的VAD响应延迟速率。

单次最大输入限制暂定为800个字符。

### 4.3 边界与排除项
- ❌ 离线版本（完全依赖网络）
- ❌ 账户系统 / 跨设备同步

## 5. 非功能性需求

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 易用性 | 从打开程序到首次输入 ≤2 次点击 | 操作路径计数 |
| 响应速度 | 停止说话 → 文字显示 ≤2 秒 | 程序内计时 |
| 成本 | 单次识别 < 0.01 元 | 按 API 官网价格估算 |
| 稳定性 | 连续使用 20 次不崩溃 | 手动测试 |

## 6. 技术选型（最新决策）

> 原计划使用本地模型（Faster-Whisper），实测中文效果不理想。**现已改为线上科大讯飞API**，以平衡准确率、速度和成本。

## 最终选型：讯飞实时语音转写大模型

**为什么？**
- 讯飞提供海量免费额度，准确率最高，适合演示。
- 两者均可桌面程序调用，无需自建模型。
