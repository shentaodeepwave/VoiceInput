## 2. 项目背景与目标

### 痛点
手动打字效率低，尤其在多任务场景下，频繁切换打断思维。语音输入可以解放双手，提升文本输入速度。  
考虑到当下的程序员行业，与 Agent 交互开发逐渐成为主流，作者认为可以开发一款一键傻瓜式语音转文字输入法助手，彻底抛弃传统的手动键入-输出式交互逻辑。

### 真正的痛点
> 手动和 agent 打字对话太累了，我们想躺着只动嘴就能奴役 AI。

### 核心目标
制作一个**轮椅级友好的语音输入法** —— 保证你甚至连鼠标都没有的情况下，文本输入速度不输金山打字王。

### 比赛要求对齐
- 准确度：安静环境下 ≥95%
- 易用性：打开程序 → 点击录音 → 说话 → 出文字，不超过 2 步
- 响应速度：实时显示（流式识别）
- 成本：单次识别 < 0.002 元

## 4. 功能范围（DoD）

### 4.1 P0 核心功能

| 功能点 | 用户故事 | 验收标准 |
|--------|----------|----------|
| 麦克风权限 | 作为用户，我希望程序启动时自动申请权限 | 启动后弹窗请求；若拒绝，提供设置入口重新授权 |
| 语音录制 | 我希望点按按钮开始/结束录音（默认模式） | 单击麦克风按钮开始录音，再次单击停止 |
| 文字转写 | 我希望说的话能准确变成文字 | 调用讯飞大模型流式 API，错误率 <10%（安静环境） |
| 文本编辑 | 我可以修改识别错误，一键复制或清空 | 文本框可手写编辑；提供“复制”“清空”按钮 |

### 4.2 P1 增强功能

| 功能点 | 说明 |
|--------|------|
| 实时流式显示 | 识别过程中，文字逐字实时追加到窗口文本框和光标所在输入框 |
| VAD 静音自动停止 | 检测到静音 ≥ 用户设定时长（0.5~5.0s 可调）自动结束录音，提升效率 |
| VAD 多档位/DIY | 提供“快速响应”、“标准”、“深思熟虑”三档快捷模式，同时支持用户自定义静音延迟秒数 |
| 全局快捷键 | 默认 `Ctrl+Shift+R`，用户可自定义，用于开始/停止录音及唤起窗口 |
| 系统托盘 | 最小化到托盘，右键菜单包含：隐藏窗口、设置、关闭程序 |
| 长按模式 | 设置中可切换为“按住说话，松开停止”的录音模式 |

### 4.3 P2 点睛功能（新增）

| 功能点 | 说明 |
|--------|------|
| 识别历史记录 | 自动保存最近 10 次识别成功的文本（带时间戳），用户可通过历史面板查看、复制或重新填入文本框。纯前端实现，不增加服务器成本 |

### 4.4 边界与排除项
- ❌ 离线版本（完全依赖网络）
- ❌ 账户系统 / 跨设备同步
- ❌ 多语种切换（仅支持中英文混合）

## 5. 非功能性需求

| 指标 | 目标值 | 测量方式 |
|------|--------|----------|
| 易用性 | 从打开程序到首次输入 ≤2 次点击 | 操作路径计数 |
| 响应速度 | 流式识别：边说边出字，最终延迟 ≤1 秒 | 主观体验 + 日志记录 |
| 成本 | 单次识别 < 0.01 元（实际约 0.002 元） | 按讯飞官方定价估算 |
| 稳定性 | 连续使用 20 次不崩溃 | 手动测试 |
| 历史记录 | 最多保留 10 条，程序重启后不清空（使用 localStorage） | 功能验证 |

## 6. 技术选型（最终决策）

> 原计划使用本地模型（Faster-Whisper），实测中文效果不理想。**现已改为线上科大讯飞实时语音转写大模型**，以平衡准确率、速度和成本。

- **主 API**：讯飞实时语音转写（WebSocket 流式）
- **备用方案**：若讯飞出现故障，降级为非流式标准版 API（保证演示不中断）
- **前端框架**：Electron + HTML/CSS/JS
- **历史记录存储**：前端 `localStorage`

**为什么选择讯飞？**  
- 提供海量免费额度（新用户 50 万次），准确率最高（官方 99.5%+）
- 支持流式返回，符合实时性要求
- 可直接从桌面程序调用，无需自建后端
